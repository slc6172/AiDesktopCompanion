# 疑難排解

依「你在畫面上看到什麼」編排。找到跟你一樣的訊息,照「原因」與「處理」做。

> 撰寫日期:2026-11-01。
>
> **哪些是實測的:** 標有「**實測**」的條目,是專案維護者在 Windows 上實際遇到並解決的(目前只有 Electron 下載太慢那一條)。**其餘條目依程式行為推導**:訊息文字逐字取自程式本身,原因與處理是根據程式碼與設定推得,尚未在真實環境逐一重現。遇到文件沒寫到的狀況,請看最後的「還是不行」。

## 先做這三件事

1. **想看程式在輸出什麼:** 不要用 `run.bat`,改雙擊 `run-debug.bat`。它會保留命令列視窗,你能即時看到訊息與錯誤。
2. **看記錄檔:** `data\app.log`(用記事本打開,看最下面最新的幾行)。程式沒有命令列視窗時,所有輸出都寫在這裡。
3. **把完整的錯誤文字留下來:** 錯誤對話框的字、`app.log` 最下面的幾行,是別人幫你查問題時最需要的東西。

## 啟動不了

**`run.bat` 啟動成功時,命令列視窗會立刻消失,這是正常的。** 只有安裝不完整時,它才會停住並顯示下面其中一則訊息(英文是故意的:批次檔只能放 ASCII 字元)。

### 「The Python virtual environment (.venv) was not found in this folder.」

- **原因:** 專案資料夾裡沒有 `.venv`,還沒建立虛擬環境,或你在別的資料夾執行。
- **處理:** 照 [安裝教學](install.md) 第 3 節建立:`python -m venv .venv`,再 `.venv\Scripts\python -m pip install -r requirements.txt`。

### 「The Python packages are not installed in .venv. Run:」

- **原因:** 虛擬環境有了,但套件還沒裝進去(或裝到一半失敗)。
- **處理:** 執行 `.venv\Scripts\pip install -r requirements.txt`,看有沒有紅字錯誤。

### 「Electron (the pet window) is not installed, or its program file is missing.」

- **原因:** 桌寵視窗(Electron)沒裝好,或下載到一半、或手動放置時放錯位置。
- **處理:** 見下一節「安裝桌寵視窗(Electron)時的問題」。

### 輸入 `python` 或 `pip` 說找不到

- **原因:** 安裝 Python 時沒有勾選「Add python.exe to PATH」。
- **處理:** 重新執行 Python 安裝程式並勾選;或把指令改成 `py -3 -m pip ...`、`py -3 -m venv .venv`。

### 跳出對話框「程式無法啟動」

對話框內容是「程式無法啟動:」加上原因,最後一行是記錄檔的位置(`data\app.log`)。常見原因:

| 對話框裡的原因 | 處理 |
|---|---|
| 找不到 Gemini API 金鑰 | 還沒設定金鑰。執行 `.venv\Scripts\python app.py --set-key`;若改用環境變數,**改完要關掉並重開 PowerShell**。見 [安裝教學](install.md) 第 5 節 |
| 找不到人設檔 | `persona.md` 不存在。把 `persona.example.md` 複製一份,命名為 `persona.md`:`copy persona.example.md persona.md` |
| 找不到 Electron | 見下一節 |
| 其他 | 把對話框的完整文字與 `data\app.log` 最下面幾行留下來,見最後的「還是不行」 |

### 沒有任何視窗、也沒有訊息

- **原因:** `run.bat` 把程式放在背景啟動,沒有命令列視窗,遇到非預期錯誤時只會寫進記錄檔。
- **處理:** 改雙擊 `run-debug.bat` 看輸出,並查 `data\app.log`。

### 連接埠被佔用

不用處理。程式從 8000 開始找,被佔用就自動換一個。

### 關掉之後再開,卻沒反應或開不起來

- **原因:** 上一次的程式沒有完全結束,還有程序留在背景。
- **處理:** 開工作管理員,結束 `pythonw.exe`(沒有視窗的 Python)與 `electron.exe`,再重新啟動。正常用工具列的退出鈕或系統匣「結束程式」離開,不會留下殘留程序。

## 安裝桌寵視窗(Electron)時的問題

### `npm install` 卡在 Electron、或慢到不行(實測)

- **現象:** 在 `electron` 資料夾執行 `npm install`,停在最後下載 Electron 執行檔那一步,很久沒有進度,或要等非常久。
- **原因:** `npm install` 的最後一步會從 GitHub 的官方 release 下載一個約 150 MB 的執行檔(`electron-v45.2.2-win32-x64.zip`)。到 GitHub 的連線在某些網路環境下很慢。維護者在台灣就遇到了:預設路線可以完成,但非常慢。
- **處理:** 改用**手動下載**:用 `npm install --ignore-scripts` 略過執行檔下載,自己用瀏覽器或下載工具取得壓縮檔、核對雜湊、解壓縮到 `dist`、寫入 `path.txt`。完整步驟(含 PowerShell 與 cmd 兩種語法)見 [安裝教學](install.md) 的「路線 C:手動下載」。維護者實際走這條路完成安裝。
- **補充:** 設定 npm registry 鏡像**幫不到**這個問題,因為慢的是 GitHub 那一包,不是從 npm 抓的小套件。

### 錯誤「Electron failed to install correctly. Please delete `node_modules/electron` and run "npx install-electron --no" manually.」

- **原因:** Electron 套件找不到 `path.txt` 或 `dist\electron.exe`,而且也沒能自己把它下載下來(下載失敗、中途被中斷,或手動放置時沒有寫 `path.txt`)。
- **處理:** 在 `electron` 資料夾執行 `node node_modules\electron\install.js` 重新下載並安裝(這就是訊息所說的那個安裝程式);下載太慢就改走 [安裝教學](install.md) 的路線 C。仍然失敗就刪掉 `electron\node_modules` 資料夾,重新 `npm install`。

### 錯誤「Generated checksum for "…" did not match expected checksum.」

- **原因:** 下載到的 Electron 檔案與官方發佈的雜湊不一致:下載不完整、被中途截斷,或來源提供的不是官方檔案。安裝程式拒絕使用它,這是保護機制。
- **處理:** 重新下載一次;換個網路或下載工具;**不要**忽略這個錯誤硬用。手動下載的核對方法見 [安裝教學](install.md) 的步驟 C3。

### `npm install` 很快就結束,但 `run.bat` 說 Electron 沒裝好

- **原因:** `npm install` 沒有執行「下載 Electron 執行檔」那一步:你用了 `--ignore-scripts`、你的 npm 設定裡 `ignore-scripts` 是開的,或那一步失敗了。
- **處理:** 在 `electron` 資料夾執行 `node node_modules\electron\install.js` 補上;或照 [安裝教學](install.md) 的路線 C 手動放置。

### 手動放好了,`run.bat` 還是說 Electron 找不到

依序檢查:

1. `electron\node_modules\electron\dist\electron.exe` 這個檔案**真的存在**,而且是直接在 `dist` 底下(不是 `dist\electron-v45.2.2-win32-x64\electron.exe`:用檔案總管「解壓縮到資料夾」會多一層)。
2. `electron\node_modules\electron\path.txt` 存在,內容只有 `electron.exe` 一行字,**結尾沒有換行**。用 [安裝教學](install.md) 的 `Set-Content ... -NoNewline` 寫入最保險。
3. 在專案資料夾執行 `Test-Path electron\node_modules\electron\dist\electron.exe` 應該印出 `True`;`Get-Content electron\node_modules\electron\path.txt` 應該印出 `electron.exe`。

## 對話

### 角色說「我今天說太多話了,先讓我休息一下,晚點再聊好嗎?」

- **原因:** Gemini 回報請求次數超過上限(429),通常是免費額度用完了。
- **處理:** 稍後再聊;免費額度隔天(依 Google 的重置時間)恢復。也可以用環境變數 `COMPANION_MODEL` 換一個額度較多的模型(見 [設定參考](configuration.md))。失敗的那一回合不會被存進紀錄。

### 角色說「網路好像不太順,可以再說一次嗎?」

- **原因:** 等 Gemini 回應逾時(預設 20 秒)。
- **處理:** 按畫面上出現的「重試」,或直接再說一次。失敗的回合不會被存進紀錄,重試不會重複。網路正常卻常發生,可以調高 `COMPANION_LLM_TIMEOUT_MS`。

### 角色說「我剛剛恍神了一下,可以再說一次嗎?」

- **原因:** Gemini 服務暫時出錯或忙碌(伺服器錯誤)。
- **處理:** 稍後再試。

### 回應太慢(首音超過 5 秒)

- **原因:** 模型回應慢、人設太長、免費額度尖峰時段,或網路慢。
- **處理:** 用 `.venv\Scripts\python smoke_gemini.py "嗨"` 看「首句」要多久;縮短人設,並在人設裡要求角色每次回覆 1 到 3 句;必要時換模型。

## 聲音輸出

### 畫面出現「語音暫時不能用,先用文字陪你聊。」

- **原因:** 語音合成連不上(預設的 Edge 語音需要連網),這一輪自動改成純文字。
- **處理:** 確認有網路;跑 `.venv\Scripts\python smoke_tts.py` 單獨測試語音。

### 有文字、沒聲音,也沒有任何提示

- **原因:** 系統或應用程式音量被靜音;或 `tts.enabled` 設成了 `false`、環境變數 `COMPANION_TTS` 設成了 `off`。
- **處理:** 檢查 Windows 音量混合器裡這個程式有沒有被靜音;檢查設定,見 [設定參考](configuration.md) 的 4.1 節。

### 聲音是女聲,想換成男聲

見 [設定參考](configuration.md) 的「角色的聲音是女聲還是男聲」。

## 語音輸入

### 按住說話沒反應,或畫面出現「麥克風沒有授權或無法使用」

- **現象:** 按住「🎤 按住說話」(或 F2)沒有錄音,對話面板出現一行以「麥克風沒有授權或無法使用」開頭的提示。
- **原因:** 桌寵視窗會直接使用麥克風,不會彈出詢問權限的視窗。**按住說話時,任何錄音失敗都會顯示這同一句**,所以它可能是:Windows 的麥克風隱私設定擋住了桌面應用程式、電腦沒有可用的麥克風、或麥克風被別的程式獨佔。
- **處理:**
  1. 到 Windows 設定的「隱私權」(Windows 11 是「隱私權與安全性」)→「麥克風」,確認允許桌面應用程式存取麥克風。(各版本名稱略有不同。)
  2. 確認系統的輸入裝置有選到你要用的麥克風,而且別的程式(視訊會議等)沒有獨佔它。
  3. 面板沒打開也不會有反應:按住說話的按鈕在對話面板裡。

### 持續聆聽出現「持續聆聽初始化失敗」

- **現象:** 按「🎙️ 持續聆聽」之後,面板出現「持續聆聽初始化失敗」,並說明要確認麥克風可用、Windows 允許桌面應用程式使用麥克風、這支麥克風能啟用回音消除。
- **原因:** 持續聆聽**需要麥克風啟用回音消除**。如果你選的輸入裝置沒有啟用回音消除、或抓不到麥克風,就不會啟動。
- **處理:** 換一支麥克風或換一個系統輸入裝置再試;**按住說話仍然可以用**,提示裡也是這樣建議。

### 畫面出現「語音輸入已啟用,但找不到 Groq API 金鑰,所以先關閉麥克風(仍可打字)。」

- **原因:** 語音辨識用 Groq,還沒設定金鑰。
- **處理:** 執行 `.venv\Scripts\python app.py --set-key-groq`(或設環境變數 `GROQ_API_KEY`),重新啟動。不想用語音的話不用處理,仍然可以打字。

### 角色說「語音辨識暫時不能用,可以再說一次或用打字嗎?」

- **原因:** 呼叫 Groq 語音辨識失敗(網路、額度或服務暫時出錯)。
- **處理:** 再說一次,或改用打字。

### 角色說「沒聽清楚,可以再說一次嗎?」

- **原因:** 辨識器沒有聽出內容,或這段聲音被防呆過濾丟掉(雜音、回音)。**連續 3 次**沒聽清楚,持續聆聽會自動關閉並提示你。
- **處理:** 靠近麥克風、降低環境噪音;最有效的是**戴耳機**。反覆發生的話,看 [設定參考](configuration.md) 的 4.2 節調整過濾。

### 持續聆聽出現你沒說的話(通常是外文)

- **原因:** 角色的聲音從喇叭漏回麥克風,或辨識器遇到雜音時自己編出一句常見的話。
- **處理:** 先**戴耳機**。再看 [設定參考](configuration.md) 的 4.2 節:確認 `stt.filter` 開著;想根治就照那裡的「量測回音」步驟決定 `ui.speaking_boost`。

### 持續聆聽時,角色的聲音忽然變小一下又恢復

這是正常的「候選插話」:偵測到聲音但還沒確認是不是你,所以先壓低角色的音量;確認不是人聲就恢復。常常發生代表回音偏大:降低喇叭音量、戴耳機,或照 [設定參考](configuration.md) 量測回音。

### 持續聆聽一直誤觸發

- **原因:** 環境吵雜,或麥克風與喇叭的回音消除效果不好。
- **處理:** 戴耳機;調高環境變數 `COMPANION_VAD_MIN_MS`(太短的聲音不送出);或改用按住說話。

## 視窗與操作

### 角色點不到,工具列也點不到

- **原因:** 「穿透」開著而且工具列收起來了,滑鼠點擊會穿過視窗。
- **處理:** 在系統匣的圖示按右鍵 →「關閉穿透」。

### 角色不見了

- **處理:** 先在系統匣的圖示按右鍵,看選單是不是「顯示角色」(角色被隱藏了),點它。仍然看不到,關閉程式,刪除 `data\window-state.json`(視窗位置檔,下次啟動會重新擺放)。

### 角色蓋住我的全螢幕簡報或工作列

- **原因:** `ui.on_top_level` 設成了 `screen-saver`,會蓋過工作列與部分全螢幕程式。
- **處理:** 改回 `normal`(見 [設定參考](configuration.md) 4.3 節),或把工具列的 📌 置頂關掉。

### 想離開程式

工具列最上方的退出鈕(按一次變紅、再按一次結束),或系統匣圖示右鍵 →「結束程式」。

## 動畫與服裝

### 動畫沒出現,只有表情符號

- **原因:** 這是還沒放影片、或影片位置與檔名不對。影片必須放在 `clips\<服裝名>\` 底下,**檔名必須是狀態名稱**,例如 `idle.webm`、`talking-happy.webm`,而且那個資料夾至少要有 `idle`。直接放在 `clips\` 這一層的影片不會被使用。
- **處理:** 見 [動畫製作教學](animation-tutorial.md) 的檔名表。啟動時的提示(「找不到任何可用的服裝資料夾…」)也會告訴你缺什麼。

### 動畫切換怪怪的

缺少的狀態會自動退回其他動畫,這是正常的。補齊 `talking-neutral` 和 `idle` 最有效。切換表情時有鬼影,是因為各張底圖的角色位置或大小不一致。

### 對角色說「換成睡衣」沒換

- **原因:** 沒有叫「睡衣」的服裝資料夾,或名稱對不上。
- **處理:** 確認 `clips\睡衣\idle.webm` 存在;想用別的說法(例如「睡袍」),在 `config.json` 的 `outfit.aliases` 設定別名,見 [設定參考](configuration.md)。

## 記憶、時間、照片、資料

### 想重置一切

關閉程式,刪除 `data\history.db`。記憶與對話會全部清空,下次啟動會建立全新的資料庫。

### 角色把「(距上一句約…)」之類的字眼說出口

- **原因:** 時間註記是系統加給模型看的,模型偶爾會把它當成說話習慣念出來。
- **處理:** 先把 `time.enabled` 設成 `false`,見 [設定參考](configuration.md) 4.5 節。

### 設定了 `time.timezone`,時間還是不對

Windows 需要 `tzdata` 套件才認得時區名稱:重新執行 `.venv\Scripts\python -m pip install -r requirements.txt`。名稱要是 IANA 格式(例如 `Asia/Taipei`);填錯會悄悄退回電腦的時區。

### 啟用了照片,卻沒有拍照功能

啟動後第一次對話會出現「拍照功能已啟用,但缺少:…,所以先關閉。」,冒號後面列出缺的東西(金鑰或帳號 ID)。照 [設定參考](configuration.md) 4.7 節補齊。

### 啟用了上網查資料,卻沒有作用

出現「上網查資料已啟用,但找不到 TinyFish API 金鑰,所以先關閉。」就是缺金鑰:執行 `.venv\Scripts\python app.py --set-key-tinyfish`。

## 還是不行

1. 用 `run-debug.bat` 重現一次,保留命令列視窗的完整輸出。
2. 取 `data\app.log` 最下面的幾行。
3. 去掉裡面的金鑰與你不想公開的對話內容後,到專案的 GitHub 頁面開一個問題(issue),附上:你做了什麼、預期發生什麼、實際發生什麼,以及上面兩樣輸出。**金鑰絕對不要貼出來**,若不小心貼了,請立刻到該服務重新產生金鑰。
