# AI 陪伴專案 — 第五階段規劃(Part 9):Electron 全身桌寵介面

**狀態:implemented(票 34–44 全部完成;Windows 實機驗收待做)**

## Problem Statement

`future.md` 要求的是一個「直向全身、無邊框透明、預設完全乾淨」的桌面懸浮角色,對話與控制都收在可展開的面板裡。現有專案的顯示層與這個目標有幾處結構性差距:

1. 現在的頁面是「上面舞台、下面對話紀錄、底部輸入列」的整頁版面,桌寵模式(`?pet=1`)只是用 CSS 把對話紀錄藏起來、改放一行字幕。這不是 `future.md` 想要的「角色 + 右下角小工具、其他全部收起來」。
2. 舞台是 380 × 320 的橫幅區塊,不是 9:16 的全身直向構圖。
3. 同時維持四種視窗模式(`edge`、`pet`、`electron`、`browser`),其中 `edge` 與 `pet` 做不到透明、置頂、穿透,版面卻要為它們維持相容。
4. 現有滑鼠穿透只是「角色/輸入區以外自動穿透」,沒有使用者可控的開關;沒有置頂開關、縮放控制、拖曳握把;視窗位置與大小重開就重置。
5. 對話面板、圖片拖放、多行輸入、未讀提示、收合狀態下的錯誤與提示去處,都還沒有定義。

## Solution

**只保留 Electron 一種版面**,把顯示與操作層整個重做;功能面(Gemini、Groq 語音辨識、TTS 備援、好感度/心情、主動發言、圖片、持續聆聽、記憶)**全部沿用,不改後端行為**。

- 單一透明無邊框視窗,由左到右是「角色區 / 工具列欄 / 面板區」。預設只看得到角色與右下角一顆半透明 ⚙,沒有字幕、狀態文字、對話氣泡。
- ⚙ 展開縱向工具列(拖曳握把、置頂、穿透、縮放 +/-、對話)。對話鈕展開從右側滑出的面板,面板內有對話紀錄、圖片、輸入、語音控制。
- 區域式自動穿透常駐,工具列的穿透開關則是「連角色本體也穿透」。
- 位置、置頂、縮放跨重啟記住。
- 角色素材先用 emoji 佔位,全身短片等程式完成後另行重做。

## User Stories

**呈現與佈局**
1. 身為使用者,我想要角色是一個沒有任何視窗框、背景方塊的全身直向角色,像一個放在桌面上的物件。
2. 身為使用者,我想要預設畫面只有角色和一顆小小的 ⚙,沒有字幕、狀態文字或氣泡,畫面極致乾淨。
3. 身為使用者,我想要點開對話面板才看到文字紀錄,不想要它一直顯示。
4. 身為使用者,我想要面板收合時發生的錯誤與提示不會打斷我,而是安靜地累積成未讀紅點。

**視窗操作**
5. 身為使用者,我想要按住握把或直接拖角色本體,就能把整個視窗(角色與工具列一起)移到不擋工作的位置。
6. 身為使用者,我想要一個置頂開關,控制角色是否永遠在最上層。
7. 身為使用者,我想要一個穿透開關,開啟後角色本體也不擋滑鼠,完全不影響我工作,而且一定有辦法把它關回來。
8. 身為使用者,我想要 `+`/`-` 按鈕等比例縮放角色,適應不同解析度螢幕,並且重開程式後維持上次的位置、置頂與大小。
9. 身為使用者,我想要角色透明區域永遠不擋我點下面的視窗。

**對話與語音**
10. 身為使用者,我想要在面板裡用多行輸入框打字溝通,Enter 送出、Shift+Enter 換行。
11. 身為使用者,我想要點選或拖拽圖片到面板,連同文字一起送給角色。
12. 身為使用者,我想要在面板裡按住說話,放開就送出;也想要一個持續聆聽開關,開啟後不用按鍵直接對話。
13. 身為使用者,我想要面板收合後持續聆聽仍然運作,並且從 ⚙ 上的小綠點看得出麥克風開著。
14. 身為使用者,我想要需要時能把「啟動就持續聆聽」寫進設定檔,不用每次手動打開。

**維護**
15. 身為專案擁有者,我想要舊的 `edge`/`pet` 模式、pywebview 與相關頁面程式碼被移除,不再為它們維持相容。

## Implementation Decisions

### A. 範圍:只保留 Electron

- **刪除:** `edge`、`pet`(pywebview)兩種模式、`run-pet.bat`、`requirements-pet.txt`、`--opaque`/`--no-top` 參數、`?pet`/`solid` 網址參數與 `body.pet` 相關 CSS、舊的整頁 `#log` 版面、`#caption` 字幕、舞台上的 `#state` 狀態文字、Edge 尋找與 edge-profile 相關程式碼、SETUP/README 中對應章節。
- **預設模式改為 `electron`。** 找不到 Electron(沒做過 `npm install`)時,用錯誤對話框提示「請安裝 Node.js,並在 `electron/` 資料夾執行一次 `npm install`」。沿用現有 `show_error()`。
- **保留 `--mode browser`,只供開發除錯。** 它不是第二種版面:同一份頁面在沒有 `window.companionShell` 時,置頂、穿透、縮放、握把自動停用(按鈕灰掉或不顯示),其餘照常運作。理由:沙盒與 CI 跑不了 Electron,新版面只能靠一般瀏覽器開頁驗證。`COMPANION_FAKE=1` 離線試玩也依賴它。
- **打包(選項 A):** 這輪只支援從原始碼用 `run.bat` 啟動。`build.bat` 不動,README 與 SETUP 註明「PyInstaller 打包版暫不支援桌寵外殼」。理由:`electron/node_modules/.bin/electron` 是 Node 腳本(已實際安裝確認),執行時需要 Node 在 PATH;一併打包是另一個獨立工程。**這是已知的功能倒退,見 Further Notes。**
- **功能面不變:** 後端 `server.py` 的 `/chat`、`/chat/audio`、`/chat/proactive`、`/history`、`/avatar`、`/config` 契約不動(`/config` 只新增 `ui` 區塊,見 F)。`TurnEngine`、`CharacterPlayer`、`VoiceActivityDetector`、`ClipSwitchDebouncer` 不動。

### B. 視窗結構與尺寸

- **單一透明視窗**:`frame:false`、`transparent:true`、`hasShadow:false`、`resizable:false`(大小由縮放決定,不讓使用者拖邊框)、`skipTaskbar:false`。
- **三欄版面,視窗寬度與面板是否展開無關:** 角色區 + 工具列欄 48px + 面板區 340px。面板區收合時整塊透明且不收滑鼠。**面板展開/收合只用 CSS 滑動,不 resize 視窗**(避免 Windows 透明視窗 resize 時閃爍)。
- **角色區 9:16**,100% 時 360 × 640。
- **視窗高度 = max(角色區高度, 560)**:縮放到 50%(角色區 320 高)時,視窗仍保留 560 高,讓面板有足夠高度可用;角色與工具列都**貼視窗底部**,面板也貼底,高度為 `min(視窗高度, 640)`。
- **縮放:** 只影響角色區與視窗尺寸,工具列與面板維持固定大小。`+`/`-` 每次 ±10%,範圍 50%–150%,上限另受「角色區高度 ≤ 目前螢幕工作區高度」限制。縮放時視窗**左下角固定不動**。
- **位置限制(寫規格時補上的洞):** 拖曳與縮放時,視窗必須保持「角色區 + 工具列欄」完全位於某個螢幕工作區內(讓 ⚙ 永遠點得到);只有面板區允許超出螢幕。
- **面板展開超出工作區右緣時,** 主行程把整個視窗往左移到放得下,收合後**不移回**,並記住新位置。
- **首次啟動位置:** 主螢幕工作區右下角。存檔位置若不滿足上一條限制(例如換了螢幕組合),退回首次啟動位置。

### C. 工具列

- **預設只露出右下角一顆半透明 ⚙。** 滑過或點擊後向上展開縱向列,由上而下:**(1) 拖曳握把 (2) 置頂 (3) 穿透 (4) 縮放 `-`/`+` (5) 對話**。
- 滑鼠離開工具列後 2 秒自動收回;**面板開著時不自動收回**。
- 平時 50% 透明,滑過 100%。已開啟的開關(置頂、穿透)高亮。
- **⚙ 角落小點:** 紅點 = 面板收合期間有未讀訊息;綠點 = 持續聆聽中。兩者可同時顯示。
- **不加麥克風按鈕。** 面板收合時,語音靠「持續聆聽」(已開啟的話在面板收合後繼續運作)。
- **系統匣選單**改為:「顯示/隱藏角色」、「關閉穿透」(逃生門)、「結束程式」。移除目前沒有對應畫面的「設定」項。
- **隱藏角色時自動關閉持續聆聽**(寫規格時補上:避免看不見的程式還開著麥克風)。再次顯示後不會自動恢復,需手動開啟。

### D. 穿透與拖曳

- **區域式自動穿透常駐:** 視窗建立時就是穿透狀態(`setIgnoreMouseEvents(true, {forward:true})`),滑鼠進入「互動區」才切成接收事件。互動區 = 角色區中間 `hit_width_ratio`(預設 0.6)寬度的矩形 + 工具列欄上目前可見的元件 + 面板(僅展開時)。
- **穿透開關(工具列 (3)):** 開啟後角色矩形不再算互動區,只剩工具列(含開關本身與握把)與面板可點。關閉方式:再點一次開關,或系統匣「關閉穿透」。**啟動時永遠是關。**
- **命中判斷寫成單一純函式**(見 G),日後要換成逐像素 alpha 判斷只改這一處。**逐像素判斷這輪不做**:AIRI 對 canvas 取樣,我們是 `<video>`,需要先有帶 alpha 的素材才能實測,另開票券。
- **拖曳為 JS 驅動:** 工具列握把與角色本體共用同一套邏輯——按下時渲染行程通知主行程,主行程用 `screen.getCursorScreenPoint()` 輪詢游標、`setPosition()` 移動視窗,放開結束。**完全不使用 `-webkit-app-region`**(它會讓角色收不到點擊、且 Windows 右鍵會跳系統選單)。拖曳期間暫時關閉穿透。拖曳結果同樣受 B 的位置限制約束。
- **置頂:** 預設開啟。層級由 `ui.on_top_level` 決定:`"normal"`(預設,`setAlwaysOnTop(true)`)或 `"screen-saver"`(Windows 上會蓋過工作列與部分全螢幕程式,AIRI 採用此層級)。

### E. 對話面板

- **由上而下:** ① 標題列(收合 ×)→ ② 對話紀錄(可捲動,沿用現有訊息渲染、情緒標籤、首句/首音秒數)→ ③ 圖片預覽列(有圖才出現)→ ④ 輸入列(多行輸入框 + 🖼️ + 送出)→ ⑤ 語音列(按住說話 + 持續聆聽開關)。
- 340px 寬度夠放完整文字標籤,按鈕恢復顯示中文(不再需要 icon-only 的窄版處理)。
- **輸入框多行:** Enter 送出、Shift+Enter 換行、最多長到 5 行後捲動。輸入法組字中(`isComposing`)按 Enter 不送出。
- **圖片:** 整個面板為放置區(拖放),保留 🖼️ 點選按鈕;維持單張、15MB 上限、`FileReader` 讀成 base64 的現有機制;**貼上(paste)這輪不做**。面板本身為 `no-drag`。
- **語音:** 持續聆聽開啟時,按住說話變灰(沿用現有行為)。F2 維持現狀(視窗有焦點時才有效,不做全域快捷鍵)。
- **面板展開後,點面板外不自動關閉。** 只能用標題列 × 或工具列對話鈕收合。
- **收合期間的訊息去處:** 錯誤、提示(`notice`)、「語音暫時不能用」、「連不上伺服器」、「持續聆聽已關閉」說明、主動發言的文字,**一律進對話紀錄**;收合時累積未讀計數,在 ⚙ 顯示紅點;**不自動展開面板**。重試按鈕留在紀錄裡的失敗訊息上。載入 `/history` 的舊訊息不算未讀。

### F. 設定與狀態保存

- **`data/window-state.json`**(由 Electron 主行程讀寫,**不寫進使用者手動編輯的 `config.json`**):記住視窗位置、置頂、縮放。穿透、持續聆聽、面板展開狀態**每次啟動都重置**(穿透關、聆聽關、面板收合)。
- **`config.json` 新增 `ui` 區塊**(沿用既有「環境變數 > config.json > 內建預設」優先權):
  - `ui.auto_listen`(預設 `false`):啟動後自動開啟持續聆聽。
  - `ui.on_top_level`(預設 `"normal"`,可選 `"screen-saver"`)。
  - `ui.hit_width_ratio`(預設 `0.6`,合法範圍 0.2–1.0,超出範圍退回預設)。
- **傳遞方式:** `/config` 回傳新增 `ui` 區塊給頁面(`auto_listen`、`hit_width_ratio`);`launcher.py` 啟動 Electron 時以環境變數傳給主行程 `COMPANION_DATA_DIR`(`window-state.json` 的位置)與 `COMPANION_ON_TOP_LEVEL`。
- 沒有 GUI 設定頁;聲音、人設、主動發言等仍編輯 `config.json`/`persona.md`。

### G. 前端新模組 `static/shell.js`(第五個測試接縫)

與 `player.js`、`vad.js`、`clipswitch.js` 同樣採雙匯出(`module.exports` 或 `globalThis`)。純函式,不碰 DOM、不碰 Electron,**Electron 主行程也直接 `require("../static/shell.js")` 共用**同一份邏輯(從原始碼啟動才成立,與 Q13 選項 A 一致)。

| 函式 | 職責 |
|---|---|
| `clampScale(s)` / `stepScale(s, dir, maxByWorkArea)` | 0.5–1.5、每步 0.1(處理浮點誤差,輸出兩位小數)、受工作區高度上限 |
| `computeLayout(scale)` | 回傳角色區寬高、工具列欄寬、面板寬、視窗寬高(含「視窗高度 = max(角色區, 560)」) |
| `validateBounds(saved, workAreas, layout)` | 保證角色區 + 工具列欄在某個工作區內,否則回傳預設位置 |
| `placePanelOpen(bounds, workArea)` | 面板展開超出右緣時,回傳往左移後的 x |
| `hitTest(point, regions, {passthrough, panelOpen, ratio})` | 回傳該點是否為互動區(穿透判斷唯一入口) |
| `nextUnread(state, event)` | 未讀計數:面板收合時的新訊息 +1、開啟清零、歷史載入不計 |

`contextIsolation` 維持開啟,**只暴露下列最小介面**(移除舊的 `onOpenSettings`):

| 方法 | 方向 | 用途 |

### I. 與既有專案的衝突與解法(對照)

| `future.md` 的要求 | 既有專案現況 | 解法 |
|---|---|---|
| 穿透開關(整個視窗穿透) | 已有區域式自動穿透 | 自動穿透常駐;開關改為「角色本體也穿透」,系統匣逃生門 |

## 實作後的偏離與補充(實作完成後補記)

- **`passthroughChanged`:** 規格書 H 節的 IPC 表沒有這一項。為了讓系統匣選單知道 👻 穿透是否開啟(決定「關閉穿透」要不要可用),渲染→主行程多了一個 `passthroughChanged(on)`。
- **Linux 不支援 `forward` 選項:** Electron 的 `setIgnoreMouseEvents(…, {forward:true})` 只有 Windows/macOS 支援,所以 `main.js` 在 Linux 上讓穿透成為空操作(整個視窗都收滑鼠)。Windows 是目標平台,不受影響;代價是沙盒無法驗證真正的穿透。
- **環境變數無效時的語意:** `ui` 的環境變數若無效(如 `COMPANION_ON_TOP_LEVEL=bogus`),視同沒設、退回 `config.json` 的有效值,而不是退回內建預設。
- **拖曳起點偏移:** 超過 4px 門檻才開始拖曳,視窗會落後游標約門檻那麼遠(見 HANDOFF §5.16)。
- **系統匣選單隨視窗狀態重建:** 監聽視窗的 `show`/`hide` 與穿透開關,確保「隱藏角色/顯示角色」標籤永遠正確。
- **前一節「補洞」三項都已實作:** 視窗高度下限 560、拖曳/縮放時角色區+工具列欄必須留在螢幕內、隱藏角色時自動關持續聆聽。
- **驗證手法:** 沙盒可以在 Xvfb 下跑真實的 Electron(見 `docs/TESTING.md` 第五階段附錄),所以本規格 Testing Decisions 裡「視窗相關行為只能人工驗收」的範圍縮小為「Windows 專屬行為」。
